# Shogo Communication Module — Schema and API Map

Companion to `SHOGO_COMMUNICATION_MODULE_REGISTER.csv`. The register's own columns cover UI/backend/integration status per item; this document carries the two fields the task asked for that don't fit cleanly in a flat CSV cell — **DB tables/models/fields/relationships** and **API endpoints + middleware + services** — in full, per item, so "schemas/endpoints found" has a checkable answer. Source for the destination side is `add_voice_studio_tables.sql` (read in full for this document, 400 lines) and `server/voice/routes.ts`/`VoiceService.ts` (both implemented earlier this engagement). Source for the Shogo side is the 13 Voice*/CommEvent Prisma models (`prisma/schema.prisma` lines 1762–2089, read in full earlier this engagement) and the route list in `sprint8-voice-routes.ts`'s own header comment.

## Destination API surface (already implemented, `server/voice/routes.ts`)

| Method + path | Middleware chain | Service call | Notes |
|---|---|---|---|
| `GET /api/voice/calls` | `requireAuth` -> `requireVoicePermission(getPool, "read")` | `VoiceService.listCalls(organizationId)` | Org-scoped list |
| `GET /api/voice/calls/:ref` | `requireAuth` -> `requireVoicePermission(getPool, "read")` | `VoiceService.getCall(organizationId, ref)` | Includes joined `voice_call_messages`; 404 across orgs (confirmed by test) |
| `POST /api/voice/calls/dispatch` | `requireAuth` -> `requireVoicePermission(getPool, "dispatch")` (ADMIN/MANAGER only) | `VoiceService.dispatchCall(organizationId, userId, requestId, input)` | Validates via `server/voice/validation.ts`; idempotent on `ref`; enqueues a `job_queue` row (`job_type: 'voice'`) rather than calling a driver directly |
| `GET /api/voice/agents` | `requireAuth` -> `requireVoicePermission(getPool, "read")` | `VoiceService.listAgents(organizationId)` | |
| `POST /api/voice/agents` | `requireAuth` -> `requireVoicePermission(getPool, "write")` (ADMIN/MANAGER/EDITOR) | `VoiceService.createAgent(...)` | |
| `GET /api/voice/campaigns` | `requireAuth` -> `requireVoicePermission(getPool, "read")` | `VoiceService.listCampaigns(organizationId)` | |
| `POST /api/voice/campaigns` | `requireAuth` -> `requireVoicePermission(getPool, "write")` | `VoiceService.createCampaign(...)` | |
| `POST /api/voice/webhooks/dograh` | None of the above — a bespoke constant-time shared-secret check (`x-bell24h-voice-webhook-secret` header vs `DOGRAH_WEBHOOK_SECRET` env) replaces user auth, since the caller is Dograh's server, not a logged-in user | `VoiceService.findCallForWebhook(...)` then `applyCapture(...)` | 503 if secret unset; 401 if missing/wrong; never trusts an org id from the payload — looks the call up by `driver_job_id`/`ref` first |

Background processing: `server/workers/handlers/VoiceJobHandler.ts`, dispatched by `WorkerRegistry.ts`'s `case "voice":` (this engagement's fix to the pre-existing mis-routing bug — see migration report). Calls `getDriver(payload.driver).dispatch(input)` from `server/voice/voiceDriver.ts`.

**11 of the 20 Shogo routes listed in `verify-voice-pages.ts`'s header (`/voice/overview, /live, /queue, /calls, /agents, /campaigns, /hub`) have a real destination equivalent in the table above (reusing `/api/voice/calls` and `/api/voice/agents`/`campaigns` as the data source for multiple UI tabs). The remaining 9 (`/voice/scripts, /providers, /voices, /numbers, /escalations, /automation, /policies, /analytics, /receptionist, /architecture, /engine, /simulate`) have no destination route at all — schema exists for 7 of those 9 (scripts/providers/voices/numbers/escalations/automation/policies), confirmed by the table above; `/receptionist` has no schema either (see register); `/architecture`, `/engine`, `/simulate` are Shogo-internal diagnostic/demo routes with no business data, not candidates for migration.**

## Shogo source schema (13 Prisma models, `prisma/schema.prisma` lines 1762–2089)

Every one of these 13 models declares `orgId String?` — **nullable**, a real tenant-isolation weakness in the source. The destination tables above all declare `organization_id UUID NOT NULL`, correcting this. Model names: `VoiceAgent, VoiceCampaign, VoiceCall, VoiceCallMessage, VoiceScript, VoiceProvider, VoiceProfile, VoiceNumber, VoiceEscalation, VoiceAutomationRule, VoicePolicy, VoiceQueueJob, CommEvent`. Field-level detail is not re-transcribed here since every field Shogo defined that was judged relevant was already carried into the destination table list above with the same semantic meaning (renamed to `snake_case`); the one model not carried forward at all is `VoiceQueueJob` (replaced by `job_queue`, see above).
